1. Docs MCP + Chain MCP Agent · Medium

Sourced Docs MCP explanations were followed by real Chain MCP calls to totalSupply and decimals. Both reads were verified at a pinned block.

node ten.mjs compose "How do I read ERC20 totalSupply on Pharos?" --wallet 0x200a5eb1477503cfc6e64fd8116c1bb967ba22c1 --output my-compose.json --evidence my-compose-mcp.jsonl --docs-evidence my-compose-docs.jsonl
  • Sourced explanation: plan.answer and original Docs MCP transcript.
  • Same function call: result.function and original eth_call arguments.
  • Contextual output: interpretation, raw result and optional humanValue.
  • Two distinct functions: totalSupply and decimals.

compose-totalSupply · compose-decimals · README and limits

Only whitelisted read-only intents are supported. Same-provider same-block read repetition checks consistency, not independent-provider agreement. Mixed write/read requests and mismatched targets are refused.

2. Audit-Log Agent · Medium

The captured report contains 8 unique transactions. Both normal and ERC20 history reached the selected interval start in the indexer. Markdown and CSV exports are included.

node ten.mjs audit --wallet 0x200a5eb1477503cfc6e64fd8116c1bb967ba22c1 --since 2026-10-01T00:00:00Z --until 2026-10-13T23:40:17.095Z --output my-audit.json --evidence my-audit-explorer.jsonl
  • Wallet and ISO date bounds: CLI --wallet, --since, --until.
  • Categories: transfers in/out, swaps, approvals, contract interactions and failed calls.
  • Exact native/token totals and transaction links: activity.categories and activity.records.
  • Exports: audit.json.md and audit.json.csv.

audit · README and limits

Method labels/selector classification of swaps and contract calls is heuristic. Token events are indexed Transfers. Counts are activity records, with separate unique transaction counts. No USD conversion. A page cap produces an explicitly partial report; indexer completeness is not guaranteed.

3. Whale-Watching Agent · Medium

Five configurable public addresses; 4 significant USDC moves matched the configured threshold in a real Chain MCP log scan.

node ten.mjs whale --config configs/ten/whale.json --output my-whale.json --evidence my-whale-mcp.jsonl
  • Five distinct addresses: config.addresses and output.addresses.
  • Per-token threshold: config.tokens[].threshold in human token units.
  • Decoded sender, recipient, amount, mint/transfer context and known labels: moves[].
  • Combined per-address summary and fixed scanned block interval: summary and range.

whale · README and limits

The demo watchlist was selected from public onchain activity, not the user's wallets. Labels are explicit configuration; unknown addresses remain literal. This command reports a bounded recent range. Long-running cursor monitoring is a separate extension, not claimed here.

4. Wallet Risk Checker · Medium

A verified older contract sample scored low; an unverified contract with a high observed failure fraction scored medium. Five signals are evaluated with explicit unknown states.

node ten.mjs risk --wallet 0x869379f2d9df67891e0159dd2520dc1681908f10 --since 2026-10-01T00:00:00Z --until 2026-10-13T23:40:17.095Z --max-pages 3 --config configs/ten/risk.json --output my-risk.json --evidence my-risk-explorer.jsonl
  • Signals: code verification, contract age, failed history, flagged counterparties and owner unlimited approvals.
  • Risk level, numeric weights and specific reasons are included.
  • Each signal explains its meaning without labelling a wallet malicious.
  • Real low and medium/high examples: risk-clean.json and risk-observed.json.

risk-clean · risk-observed · README and limits

Both examples use bounded, partial history. Low means no observed configured flags, not proven safe or clean. An empty flagged list is unknown, not a pass. Only successful approvals sent by the checked owner are sampled; no external threat-intelligence feed is claimed.

5. Weekly Digest Agent · Medium

Current seven-day metrics are compared to the preceding seven days, with 3 distinct notable transactions. Two actual worker ticks were captured using an accelerated two-second interval. The production GitHub workflow runs Mondays at 00:00 UTC (07:00 Vietnam) and deploys the refreshed digest page.

node ten.mjs digest --wallet 0x200a5eb1477503cfc6e64fd8116c1bb967ba22c1 --period-days 7 --output my-digest.json --html my-digest.html --schedule
  • Weekly default interval: CLI 604800 seconds; GitHub schedule cron Monday 00:00 UTC.
  • Comparisons with previous period: comparisons.current/previous/delta.
  • Top three distinct transaction events: topEvents and ranking rule.
  • Publication: digest-latest.html and .github/workflows/weekly-digest.yml Pages deployment.

digest · README and limits

The accelerated demo verifies scheduling, not the passage of an actual week. Hosted starts may be delayed by GitHub. Indexer/page-cap limitations propagate into the digest. A local worker writes local HTML; the included hosted workflow supplies recurring public publication.

6. Policy Gatekeeper · Medium

One allowed read-only call and one actual denied configuration for each spend, allowlist and trusted UTC time-window rule. Denied requests did not invoke their action.

node ten.mjs policy --config configs/ten/policy.json --output my-policy.json --evidence my-policy-mcp.jsonl
  • Three configured rule types: policy.maxValueWei, allowlist and utcWindow.
  • Every request has allow/deny plus deciding rule and all-rule trace.
  • Each deny has executed=false; only allow invokes eth_call.
  • All decisions append to output.audit.jsonl.

policy-allow · policy-spend-deny · policy-address-deny · policy-time-deny · README and limits

This demo Skill gates read-only eth_call simulations. It is not a production signing gateway. No private key or broadcast method exists. UTC windows use the trusted host clock, not a client-supplied timestamp.

7. Threshold Guardian · Medium

Three distinct live signals (native balance, token supply and gas quote) were evaluated. One configurable run fired the token report; another held and did not run the report action.

node ten.mjs guardian --config configs/ten/guardian.json --output my-guardian.json --evidence my-guardian-mcp.jsonl
  • Independent chain inputs: data.observed.native/supply/gas.
  • Configurable thresholds/comparators: conditions in guardian configs.
  • Decision trace includes every value, threshold and pass/fail.
  • Captured outcomes: guardian-fire.json and guardian-hold.json.

guardian-fire · guardian-hold · README and limits

Fire performs a read-only report, not a rebalance. Supply and native balance are pinned; the gas quote is current and cannot be pinned by this API.

8. Dry-Run Executor · Medium

A successful read-only ERC20 transfer simulation estimated 79757 gas and 797570000000000 wei. An excessive transfer reverted and invoked the executor zero times.

node ten.mjs dry-run --config configs/ten/dry-run.json --output my-dry-run.json --evidence my-dry-run-mcp.jsonl
  • eth_call and estimate_gas are used without broadcasting.
  • Predicted success/revert, provider reason and estimated gas/cost are reported.
  • Token balances before and predicted balances after are included.
  • Failed simulation barrier: executorInvocations=0 and executed=false.

dry-run-success · dry-run-revert · README and limits

The successful sender is a public funded EOA used for simulation only; ownership is not claimed. Expected balances assume a standard non-fee ERC20. Gas estimate uses current state while the call/balance reads use a fixed block. Successful execution only prepares an unsigned transaction; actual signing/broadcasting is outside this build.

9. Skill + Chain MCP Flow · Medium

A single account/state request loaded the local state-brief Skill, fetched live Chain MCP balance/supply/gas/metadata, and produced a brief from those exact inputs.

node ten.mjs flow --config configs/ten/flow.json --output my-flow.json --evidence my-flow-mcp.jsonl
  • Live inputs in the same flow: data and token fields with MCP provenance.
  • One request: flow CLI and request property.
  • Order: user request → local Skill → Chain MCP reads → formatted Skill output.
  • Actual real-chain inputs and local Skill package SHA-256 are saved.

flow · README and limits

SkillEngine follows the official knowledge-package pattern; these are custom local Skills, not an invented hosted runtime or an Anvita deployment. The native balance and supply snapshot share one block; token metadata/report calls may use a later block and both are shown.

10. Doc-Grounded Builder Agent · Hard

Three different supported how-do-I requests were planned with sourced Docs MCP answers, executed through Chain MCP, and verified. An unsupported banana-on-Mars request was refused without a chain action.

node ten.mjs builder "How do I read my native PROS balance on Pharos?" --wallet 0x200a5eb1477503cfc6e64fd8116c1bb967ba22c1 --output my-builder.json --evidence my-builder-mcp.jsonl --docs-evidence my-builder-docs.jsonl
  • Docs MCP plan, cited sources and resolved target precede chain execution.
  • Only fixed read-only operations are executed; no downloaded prose is run.
  • Same-block result is read back and compared to the plan operation.
  • Three requests: total supply, token decimals and native PROS balance.
  • Unsupported/unsourced/mixed intents are refused rather than improvised.

builder-supply · builder-decimals · builder-native · builder-unsupported · README and limits

This Hard-task build has a bounded three-intent scope. It does not synthesize arbitrary contract code or deploy contracts. Verification is same-provider consistency, not independent corroboration.

All captures are dated evidence. No funds were moved. Skill packages execute locally using documented helpers. Verification of scheduled hosting is recorded separately from the accelerated local scheduler demo.
